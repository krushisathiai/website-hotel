The Sequence Diagram models the chronological message exchange for the critical Guest Check-In & Room Assignment Workflow. It illustrates asynchronous UI dispatches, RESTful HTTP payloads, JWT authorization gatekeeping, transactional controller logic, and ACID-compliant database writes via Prisma ORM to PostgreSQL.

FIGURE 4.1: Guest Check-In & Room Assignment Sequence Diagram
Chronological sequence showing token validation, transactional state synchronization, and audit logging.

Sequence Step Execution Log

Step Initiator & Target Payload / Function Transaction & Invariant Semantics
1-2 Receptionist → React SPA → Gateway PUT /api/bookings/:id/checkin Front desk triggers check-in. React transmits booking ID and Bearer JWT in request headers.
3-4 Gateway → JWT Auth Guard jwt.verify(token, JWT_SECRET) Extracts tenant hotel ID and role claims. Rejects unauthorized access with HTTP 401/403.
5-6 Gateway → BookingController checkIn(req, res) Begins atomic execution using prisma.$transaction to protect room availability invariants.
7-10 Controller → PostgreSQL Database UPDATE bookings, rooms; INSERT audit Booking status advances to CHECKED_IN; room status advances to OCCUPIED; audit log stored.
11-14 PostgreSQL → Controller → UI HTTP 200 OK + Updated Folio State changes commit; UI updates the room status badge and prompts keycard issuance.
